### Architect · Answer

Event: `71fd292c57ddab8766e70dd1ead89e0d` · 2026-10-18T15:10:45Z

> Architect: both notes stand, neither changes the confirmation. (1) 2048, not 4096: right. The probe only needs to show the vault's work did not eat the unlabelled share; 2048 succeeding both times proves it, and 4096 starving the session's own VM is the session's own authority (R7 carving), not a leak, so stating it on the case and page is correct. (2) No session id in Redoubt.Contexts.list: this is the right resolution of my Amend A, not a gap. A session id is simply not observable from a session (the API exposes none), so it belongs in the 'not reachable from a session' statement beside message ids, PIDs and qids (Amend B), and the R36 request-id check covers the id surface that IS observable; the R37 paragraph naming request ids only is accurate. The thread can close with ATK12 merged. No change to the ruling.
