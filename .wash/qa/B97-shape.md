## B97 · B97-shape — B97: empty listeners and the shared socket table

Status: **open** · Assigned to: Orchestrator · Revision: 3

### Implementer · Question

Event: `647db01f3fe8e09e67e532555a44ff7b` · 2026-10-21T00:15:34Z

> B97 shape proposal (code, not residual).
> 
> Confirmed on d66839252 (servers/ipd/src/stack.rs room/listen): the table bound (2 x max_sockets) is global; an entry lives until close/abort/disconnect (clunking fids does not release it), so one listen-scope connection can clone, listen backlog 1, accept at its cap (refill refused), close the accepted socket, repeat: each round leaves an unmetered empty listener. Image: 216 entries; once full every bucket's next clone/listen is refused too_many.
> 
> Proposal: charge the entries, not units, to the bucket. room() and listen() check the key's own entries (owner.key == bucket, lingering included) against 2 x cap(key) instead of the whole table against max_entries. Arithmetic: a bucket's sockets <= cap, and a listener with a backlog holds at least one charged backlog socket of its own, so legitimate use never passes 2 x cap; only empty listeners beyond that are refused, and the refusal falls on the holder's own bucket. Live keys are distinct admission buckets, each counted in max_sockets at max(cap, default), so the sum is <= 2 x max_sockets: table sizing unchanged, no unit/meter/Sizing change. The global check stays as a backstop (reachable only between a disconnect and the next poll's sweep of its released empty listeners, if another key takes the slot meanwhile; one sentence on the page).
> 
> Rejected: a State unit per empty listener (the accept that empties it has no reservation to pay from; refusing the accept breaks sshd at its cap); residual only (the fix is ~10 lines).
> 
> Tests: host test, bucket A fills with empty listeners and bucket B still gets its socket (fails on d66839252); a_full_table_refuses_a_listen_or_a_socket reworked to the per-bucket bound. No attack case: only a listen scope reaches it (sshd, badge 6); no session holds one. Docs: ipd.md Sizing table paragraph rewritten. OK to build?

### Architect · Answer

Event: `7e07fd67b288c89a43f1a14270fd6d73` · 2026-10-21T00:16:18Z

> OK to build, as proposed. The shape is right: the refusal lands on the bucket that caused it, the table's size and the sizing arithmetic stand, and the backstop keeps the global invariant for the one window you name. Detail recorded in the rulings file ('B97-shape').
> 
> Conditions, all small:
> 1. The per-key bound counts the key's lingering entries too, as you say: that is the TIME-WAIT rule (charged to its owner until gone) applied to entries, and the page says so in the same breath.
> 2. ipd.md 'Sizing' carries the arithmetic in your message's words: sockets <= cap; a listener with a backlog holds a charged backlog socket, so legitimate use never passes 2 x cap; live keys are at most the buckets, each counted in max_sockets at max(cap, default), so the sum over live keys <= 2 x max_sockets; the global check as the backstop and its one reachable window. And who can reach the refusal at all: a listen scope, the image's sshd, never a session; that is why there is no attack case and the host test is the attack.
> 3. The per-key count: a scan of at most 216 entries per room()/listen() is fine at this size, a kept count per key is fine too; the simplifier chooses, not the page.
> 4. The rejected State-unit alternative and its reason (the emptying accept has no reservation to pay from; refusing it breaks sshd at its cap) go in the report, not on the page.
> 
> Tests as proposed: the A-fills-B-still-gets-a-socket host test red on d66839252, a_full_table_refuses_a_listen_or_a_socket reworked to the per-bucket bound, the global backstop still tested. Tier A, small, red review as the node says; sshd-refuses-slots and the net cases unchanged in verdict.
