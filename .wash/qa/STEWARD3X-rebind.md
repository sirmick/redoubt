> Ruling: all five defaults stand, with words added. Full text and page list: .wash/local/STEWARD3X-ruling.md.
> 
> Wire: 18 reconnected (init's class), 19 server_restarted(server, slot) a send on notices, 20 rebind(slot) -> at, connection: as proposed.
> 
> Q1: accepted. Only path-bound slots announced; slot 5 (erofsd:system, the code source) a stated residual (its restart leaves every session dead; no bind replaces a code source); slot 4 never announced, rebind(4) unknown.
> 
> Q2: accepted, the Tier A invariant stated and tested: a rebind mints by the login batch's route, Kernel::connect(owner, slot, scope): the same scope, below the same kind of root (the home carve, quota shared), the same account bucket; it grants nothing the login did not. A host test asserts the re-bound connection's stamp, root and quota equal the login's, and a rebind for a slot not the session's own answers unknown. No core row, no oracle or model change.
> 
> Q3: (a) now: the agent's connections stay dead until its deadline or end_lease; agents.md and steward.md say it plainly and that the sponsor's way out is end_lease and a new start_agent. Not (b): ending a lease for a server's fault punishes the sponsor's work when the sponsor already holds the choice. (c) is the right shape when agents must outlive a server restart: a follow-up when the owner asks, not now.
> 
> Q4: accepted; the fresh-list entry is replaced only when the steward took it; after `lost` the steward stays stranded at that server until its own restart (said in the line's doc and as init.md's residual); a login between the restart and reconnected fails its home step and is refused: stated, the person retries.
> 
> Q5: accepted, through the shell's printer as [lease NAME ended] is.

> Q4 amended (appended to .wash/local/STEWARD3X-ruling.md):
> 
> 1. The order change is sound: blame while the steward is idle, reconnect when the server serves; init.md states it in that order.
> 
> 2. Measure it once on both widths with the image's data volume (walfsd-power-loss's recovery is the measurement; quote it), set SERVER_TIMEOUT at twice the measured recovery rounded up to a second, and state bound, reason and measurement on init.md; 10 s stands only if the arithmetic gives it. > 
> 3. The steward blocking in an end batch's disconnect at a recovering server: 3X states it as a residual on steward.md 'Failure and restart' with the measured number ("an end waits on each server's disconnect, each bounded by the call timeout; a recovering server costs that per connection, during which the steward serves nobody"); the fix is its own node, STEWARD3Y (drafted, needs 3X, Tier A, steward-red-2, S): per 3R the disconnect is cleanup, never the cutoff, so the end batch replies after DestroyBudget and the disconnects become deferred cleanup steps the Machine runs at its turn, each bounded short, retried with a cap, then dropped with a line (the admission freed only by the server's own restart: the residual that remains); the queue bounded by the live connections. R28/B62's rule, a wait bounded by its own deadline, then holds for the steward as a client too; 3X's reconnected path needs no disconnect of the dead records.
