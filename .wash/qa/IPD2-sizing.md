> 
> FINDING (today): the heap cap 74 does not hold every socket's buffers. A socket's buffers are 2 heap blocks of 2 pages each (+432 B smoltcp storage, measured), inside SOCKET_BYTES = 4.25 pages. Today's worst case: 84 x 17,408 = 357 pages vs the cap 74 with an idle peak of 37, so room for 8 sockets. Past that the allocation fails and ipd panics. alice 3+3 plus bob 5 = 11 is reachable at today's defaults (derived, not booted). After: 108 sockets = 459 pages, and alice's session alone (11) would crash ipd in the new case.
> 
> Ruling needed:
> (1, recommended) ipd refuses to start unless heap ≥ 74 + max_sockets x SOCKET_BYTES; image heap_pages 533, entry stays 4,096 (1,986 used). This touches all 35 test manifests running ipd plus the bench's manifest check, outside my owned paths.
> (2) Image heap only (533), rule stated, no check.
> (3, with either) Fallible new_socket: a heap gap answers too_many, never a panic.
> I recommend 1+3. I'm holding the case.

### Architect · Answer

Event: `d2e567733660ef1c96b8143df36954b1` · 2026-10-20T17:55:13Z

> Ruling: options 1 + 3, inside IPD2, not a separate B node first. IPD2 is the package that rewrites this arithmetic, and its new case is the attack that crashes ipd on main today. Detail is in .wash/local/wave-2026-10-18-rulings.md, section 'IPD2-sizing'.
> 
> 1. Count each socket once, where it lives. ipd refuses to start unless heap_pages x page >= base + max_sockets x SOCKET_BYTES. The base is the measured working set at twice its peak (74 pages today). The image's heap goes to 533 and its entry stays at 4,096.
>    In the same change, the budget term costs a State unit as a connection (CONNECTION_BYTES), not as a socket, because the buffers belong to the heap term. If that Cost change reaches past ipd's sizing, keep the double count and state it as a residual on ipd.md.
>    Every manifest with an ipd entry gets heap_pages derived the same way, and the bench's per-entry manifest check counts the heap term. Owned paths widen to those manifests and that check.
> 2. Make new_socket fallible: an allocation failure answers too_many and prints one ipd line saying an invariant broke. With (1) in place that line is unreachable, so the boot cases forbid it. It is a backstop, never the policy.
> 3. Pages. The rule and its arithmetic go on ipd.md 'Sizing' (the owning page). 'Bad arguments, or limits that do not fit its budget' is extended to cover the heap. testbench.md's memory table gets ipd's row, and SECURITY.md gets an R26 row if the case is named there. IPD2's new case must fail on main as an ipd crash or refusal; say so in the report.
> 
> Size L. The reviewer is unchanged.
