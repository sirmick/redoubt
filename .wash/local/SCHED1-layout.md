## Mechanism and scope

Change `kernel/src/sched.rs::SLICE_US` and `model/src/spec.rs::SLICE` from 10,000 to 1,000 microseconds. A pick always starts that uniform slice; the timer still arms the earliest slice end, timeout or deadline. Wake pass remains `max(own,floor)` and never preempts. Rank `(pass,tie,id)` and all four tie clauses, charge/remainder, minimum charge, free weight, rescale and inherited debt remain. `SLICE_US` also drives `Marks::audit_due` in `leave` and `pick`; preserve that within-one-slice audit rule and `sched::audit` netting. No tolerance, trace RAM, ABI, stride arithmetic or IPC change is proposed. One pass through seventeen spinning budgets is nominally 17 ms instead of 170 ms of user slices, excluding kernel work, audits and retained lead; it is no latency guarantee.

## Focused clustered-wake fixture

Add `tests/programs/src/bin/sched-cluster.rs` and `tests/sched-cluster.toml`, with one bounded host post-check in `tools/testbench/src/sched_oracle.rs` or a focused module it calls. Seed 3, `-icount shift=3,sleep=off`, `-rtc clock=vm`, checked `sched-trace`, both widths. The parent creates sixteen separate weight-100 spinner budgets, one weight-1000 busy server, and weight-1000 driver (goldfish RTC) and timer stand-ins. Each has one runnable thread when active. Children park on a startup barrier; the sixteen spinners use one future absolute `rdtime` target converted to relative `receive` timeouts, then spin through the window. Give setup ample lead; no sequential go messages during the measured release. The parent does not set pass or inspect scheduling quantum through a new call. Stand-ins take 200 wake samples each in a 16-second window, with the fixed intended offsets [100, 300, 600, 850] microseconds repeated 50 times, alternating intended zero-lead and retained-positive-lead rounds (25 of each intent at every offset). The positive-lead stand-in runs enough ordinary CPU before blocking to owe pass; the zero-lead stand-in sleeps while the cluster advances. Neither intent is accepted without trace proof. Keep the busy server spinning throughout, count the same useful loop as the existing `Spin` role, and print complete timestamped sample windows after measurement, as `LATENCY-SAMPLE`/`LATENCY-COUNT` already do. The driver reads its own RTC alarm clock; the timer reads `time_now`. They are trusted stand-ins; their samples are judged by the independent post-check net of stamped audits.

Host replay first runs existing `sched_oracle::parse/check` unchanged for rank, floor, charging/lift, audit pairs and zero drops. It reconstructs each queue rank from W/R/D/P/K, including ties. At the cluster release, require sixteen distinct spinner W records before the first later K, all sixteen still queued at that K, and pass spread at that K no more than the pass corresponding to 100 microseconds of one weight-100 spinner's CPU (derive the threshold from measured timebase ticks and `STRIDE`, never from a hardcoded pass value). Record the observed W-entry span and pass spread. This checks actual ranks and the common release, not a population count. A wake sample qualifies as zero lead only when W.pass equals the replayed floor; it qualifies as positive lead only when W.pass exceeds the floor and at least eight of the sixteen spinner ranks are strictly ahead of that W rank. Require at least 25 qualifying zero-lead and 25 qualifying positive-lead wakes for EACH of driver and timer, with at least five of each category at each programmed offset; any shortfall is a fixture failure even if p99 passes. Record for each qualified W: floor, lead in pass units, spinner ranks ahead, K records until the waker's K, and the trusted sample's gross/net elapsed time. Reject any W that cannot be uniquely joined in order to one sample for its stand-in. Require both stand-ins' p50 <=15,000 and p99 <=50,000 microseconds; zero dropped trace records. The old 10 ms IPC3 tree with the SAME fixture, seed, phase list, bound and oracle must fail a latency bound on each width, while still proving coverage; a vacuous old-control failure is insufficient.

Trace observability needs Architect review before coding: W and K carry entry, budget ID and pass, but no timestamp; I carries a timestamp, and K does not identify pid/tid. A one-thread-per-budget fixture permits repeated K of the same budget to mean repeated pick of the same thread. Stand-in IDs can be established by unique isolated setup wakes, then the nth W of each stand-in joined to its nth reported sample after checking no lost/extra wake. The I record around a timeout supplies expiry time; the trusted sample supplies service time, but a driver interrupt's W and timer I must be uniquely matched by entry/order. An exact offset relative to a K's pick instant cannot be proved directly from current K records. The programmed phase list and trace order can prove a wake landed after a busy-server K and before its slice-ending timer return; label the exact fractional phase as intended unless a sound reconstruction is demonstrated. Do not claim precise per-wake wait or phase from W/K alone. If review requires exact pick-time phase, seek an explicit scope ruling for test-only trace fields under `sched-trace`; no production instrumentation channel or trace-RAM increase is proposed. The paired experiment asks for timer work billed in the window, which existing B records can supply. Total kernel billing is not separately observable from this trace.

## Capacity and paired measurement

The existing trace ring is 16,384 pages x 128 records/page = 2,097,152 records = 64 MiB. A 16-second N=16 window at 1 ms permits roughly 16,000 slice-ending picks; even 8 records/pick, 400 wake/expiry cycles at 10 records and 16,000 U/V mark-audit pairs project about 164,000 records plus setup/destruction. Three latency windows project order 0.5 million, below capacity, but this is only an estimate: IPC3 `worst-walk` already used 1,805,322 records. The oracle must require `dropped 0`; a drop stops the candidate, without increasing RAM.

After release, compare IPC3 a0fbbcab1 (10 ms) to that exact tree plus isolated SCHED1 commits (1 ms), same dev image/QEMU/RAM/features/clocks and serial jobs. Both widths: `sched-latency` seed 3, `kernel-containment` seed 13, cluster seed 3 and identical test-only fixture overlay on old IPC3; preserve both binary/configuration identities. Reuse saved baseline logs only if seed, exact tree/configuration and every comparison field are verifiable; otherwise collect the missing paired run. For each N/window report baseline, candidate, absolute and percent delta: driver/timer/decision/deadline net and gross p50/p99/max, R10 p99 and lease-end sum; startup spinner pass spread, per-qualifying-wake lead, count ahead, intervening picks and sample elapsed; spinner work iterations per gross guest second and per audit-net guest second, server share; total picks, budget changes between consecutive K, repeated picks of the same budget, slice-ending I/O entries, timer-expiry B ticks billed in the window, R10 spans, audit count/time, trace count/drops. Normalize each count by audit-net guest seconds as well as reporting its raw count. One-thread-per-budget intervals permit K IDs to classify actual thread switches there; report other intervals separately where this is not established. General kernel time billed outside timer B/R10 is not separately present in the existing trace. Report timer work billed from B; do not label B/R10 or their sum as total switching cost or all kernel billing. Do not subtract ordinary kernel work as audit. No throughput-loss tolerance exists; report measured useful-work and switching cost, and stop for a material unexplained loss.

First post-release check is pinned sched-latency rv64/rv32, then paired and cluster negative control, serial 1..16 sweeps of sched-latency and kernel-containment, full named scheduler/budget attacks, host stride/model/differential/contracts/mutations and oracle cases, then final Tier A whole bench both widths, worst-walk, docs, format, size/unsafe and rv32.
