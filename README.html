Redoubt

A small, auditable RISC-V microkernel in pure Rust — and the runtimes that run on it. Today the runtime is beamlet, a safe-Rust BEAM (Erlang/Elixir) VM. The OS is runtime-neutral.

01The system at a glance

Redoubt is a hard fork of Xous, rebuilt for RV32 and RV64 on one width-generic code path and aimed at a specific threat: a capable adversary that has read every line of the source and controls any code it is allowed to run. The design rests on no ambient authority — a process can touch only what it was explicitly given — enforced by a tiny kernel with capabilities, budgets and information-flow labels.

Built and tested

  • rv64 + rv32 boot on QEMU virt, OpenSBI and RustSBI
  • the kernel: memory, threads, handles & endpoints, budgets, devices, IRQ receive, timer, verified boot, W^X
  • libs/: sys, rt, wire, signing, littlefs, paging
  • servers/keyd, tools/testbench
  • beamlet — runs Elixir, its compiler, IEx, OTP crypto/ssl/ssh

Designed, not built

  • init + boot manifest + loader stub
  • steward, sshd, fsd, blkd, netd, ipd, bootfsd, consoled
  • packages, projects, sharing, A/B system updates
  • FPGA cards, disk encryption, gatewayd, webd, linkd/routerd

A term to hold onto: a budget is a kernel container every process lives in. It is the unit of accounting, CPU share, revocation, information-flow labels, and identity (its account travels with every message) — one object replacing five mechanisms. RESOURCES.md · CONTAINMENT.md

02Boot flow

Firmware verifies nothing on QEMU (QEMU loads the loader directly); the link that matters is that the loader authenticates the boot bundle before executing any of it. The initrd is signature(64) ‖ tar; the signature covers "redoubt.bundle.v1\0" ‖ u64_le(len) ‖ tar, and one crate builds the preimage for both the loader and the signer so they cannot drift.

  • Built: firmware selection, loader both widths, Ed25519 verification, W^X, default-deny device grants. BOOT.md · VERIFIED-BOOT.md · libs/signing · loader/src/verify.rs
  • Designed change: the loader will load only kernel + init; init launches every other process through a system-signed loader stub from the bundle's pages. PACKAGES.md

03The kernel — objects and calls

The kernel keeps memory, threads, IPC, interrupt delivery and the timer. Nothing else. Its whole interface is a small set of objects reached through unforgeable handles, and a set of system calls whose errors and order of checks are normative so the executable model and the real kernel can be compared exactly.

04Servers

Every server is an unprivileged process in its own budget. Its authority is a set of handles, never ambient. A launcher never passes its own connection to a child: it asks the server for a fresh one, so a hostile agent started by a shell cannot share the shell's file table.

keyd's rule: a badge names one key and one purpose. Every signature is over a 32-byte digest keyd computed itself, and no operation returns a private key. A session that crashes a shared server three times (same account + label set) is logged out for 10 minutes, taken from the kernel's exit notice — never the attacker's output. 05Userland: beamlet (the OTP runtime)

The OS is runtime-neutral. beamlet runs Erlang/Elixir bytecode from the pinned OTP 28, with its own scheduler, per-process heaps and copying GC. It is verified by differential tests: every test runs on the real BEAM and on beamlet and the output must be identical. OTP's crypto, public_key, ssl and ssh run unmodified on Rust natives.

  • Built and tested against the real BEAM: userland/otp/DESIGN.md
  • Designed: beamlet's Platform retargeted to the Redoubt 9P client (WP-B1/WP-B2: console, files, launching; then IEx on the UART). USERLAND.md
  • On Redoubt, one VM = one trust domain; a new trust domain is a new VM under a new budget.

06The security model in one diagram

Capabilities bound authority (what a process can do); labels bound information (what it can leak); budgets tie both together and are the only revocation mechanism.

Mechanisms

  • No ambient authority — devices default-deny; RAM is never nameable by address; pages are zeroed
  • Verified boot — every privileged byte is authenticated first
  • W^X everywhere, including the kernel's own mappings
  • Fail closed — a violated invariant stops the machine
  • unsafe is a budget that only falls

Agents and approvals

  • Own principal, accountable sponsor, task-scoped leases
  • Delegation only narrows; assume every agent is compromised
  • Approvals are out of band: only the steward talks to ssh approve@box
  • Three blamed crashes end a session for the window

07Getting started

Everything runs in a self-contained Docker container; the host needs only Docker. A concise version of this section also lives in GETTING-STARTED.md.

1 · Toolchain

./dev.sh                 # build the image (first time), then a shell in /work
./dev.sh --rebuild       # rebuild the image after editing the Dockerfile

Installs Rust with the RISC-V bare-metal targets (riscv64imac, riscv32imac, riscv64gc), QEMU for both widths, OpenSSH, graphviz (for this page's diagrams) and the agent CLIs. The pinned OTP 28 / Elixir 1.20 toolchains live in toolchains/.

2 · Firmware (once)

./scripts/build-bios.sh  # builds the vendored RustSBI in bios/ for both widths

3 · Build the OS

./build --arch rv64              # kernel + loader
./build --arch rv32
./build --arch rv64 --programs   # also the in-guest test programs

4 · Launch it in a VM

./launch --arch rv64                       # prints the exact QEMU line, then boots; Ctrl-A X quits
./launch --arch rv64 --program log-server
./launch --arch rv32 --smp 4
./launch --arch rv64 --print-only          # show the QEMU command and exit
./launch --arch rv64 --debug               # pause with a gdb stub on :1234

launch assembles and signs the boot bundle and attaches the guest serial console to your stdin/stdout. DEBUGGING.md

5 · Run the tests

./test --arch rv64            # the whole bench
./test --arch rv64 timer      # cases whose name contains "timer"
./test --list

6 · Build an image

./mkimage                      # signed boot bundle → target/image/redoubt.bundle

Disk-image recipes (littlefs) live in image/ and are not built yet.

7 · beamlet

cd userland/otp
. tools/env.sh                 # put the pinned OTP/Elixir on PATH
cargo test                     # unit + hostile-input tests
tools/difftest                 # differential tests against the real BEAM

08Testing, and why a green run means something

One simple harness, real boots, no kernel mocks: cargo testbench boots the real kernel under QEMU with injected programs and asserts on the console. An attack case passes only on a line the attacker cannot write — the verdict comes from the kernel, a victim, or a clean power-off.

A build of the same sources with debug assertions and overflow checks (the checked profile) is a normal case option. 55 cases exercise IPC, budgets, devices, timers, loader rejections, verified-boot attacks, forged verdicts and SSH. TENETS.md tenet 6 · testbench.md · tests/

10Milestones

  • M1 — separation and containment: Alice and Bob logged in over SSH, separated; Alice's agent under a lease, contained. Every property backed by an attack test.
  • M2 — install, share, persist: packages and trust lists, projects, reboot memory, A/B system updates with rollback.
  • M3 — self-hosted development: a real agent harness through gatewayd, compilers on the box, the server APIs.
  • After M3: rv32 returned to the booted dimensions; SMP; the FPGA.
