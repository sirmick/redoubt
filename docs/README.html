Redoubt

A RISC-V microkernel in pure Rust for running hostile code under explicit authority, resource limits and information-flow labels. QEMU boots on rv64 and rv32; beamlet currently runs on the host. Native userland integration remains work in progress.

The tenets govern the design

TENETS outranks every other document. These are target constraints; STATUS records implementation gaps and evidence.

  1. Simple enough to audit: a small kernel, one mechanism per job, deletion before configuration.
  2. Secure by construction: explicit capabilities, least privilege, W^X, authenticated privileged code, fail-closed behavior, bounded unsafe code and an out-of-band approval channel.
  3. Rust: assembly only where Rust cannot reach; host test-oracle exceptions stay off target.
  4. Open standards: published hardware interfaces, formats, protocols and reproducible sources.
  5. Dependencies are part of the TCB: small, read, pinned and justified.
  6. Attack-tested: real boots, regressions, hostile inputs and a harness proved able to fail.
  7. Virtio devices: trivial-device exceptions; DMA drivers are trusted unless hardware confines them.

The label set is the isolation unit. Covert/physical channels are outside the software claim. Mediation, authority closure and the wakeup bound still have open decisions 164–166; their recommendations are not accepted rules.

The swarm method

SWARM owns execution and claims. Independent packages use isolated worktrees; one writer owns each shared hotspot. The resident architect resolves contract questions, implementers build bounded packages, and defensive, simplifier and editor reviews check the result.

Acceptance includes package tests, the full bench, rv32 compilation and the unsafe ratchet. Review can be batched for small changes; TCB/security changes get a dedicated round. Deferred review stays visible as debt and is cleared before a new wave. Keep approved rules in their specifications and current state in Claims.

What will be

PLAN owns milestone outcomes and attack acceptance:

  1. Separated SSH sessions and a leased, contained agent on QEMU.
  2. Signed packages, projects, persistent policy and A/B updates.
  3. Self-hosted development and compilers; the real-agent harness begins alongside milestone 2.

SMP follows milestone 1; required full-stack rv32 boots follow milestone 3. Current rv32 boot tests do not establish full-stack support.
